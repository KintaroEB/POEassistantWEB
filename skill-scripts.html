four ways to use your skill bar — from one key to a full target picker. PoE2 only.

⚠ All four scripts press keys Turn on input enabled in the SCRIPTING tab and bind a panic key in the HOTKEYS tab first. Then open show character current values and check which key each of your skills sits on — the keys below are only examples.
Three rules every script here follows Ready means off cooldown only — mana is not checked, so add a mana line for expensive skills. Every skill handle can be nil for the first tick or two, so each script checks it. Pick skills by key (:SkillByKey("R")) or slot, never by .Id.
1 · Basic

one skill, one condition

basicEmergency skill on low lifeneeds input

Cast a defensive skill — a guard skill, a blink, a war cry — when your life drops low. It only presses when the skill is ready, so it never wastes a press on a cooldown.

Tune: KEY (the key the slot shows), THRESH (life percent), GAP.

local KEY    = "E"    -- the slot's key, and the key we press
local THRESH = 50     -- cast below this life percent
local GAP    = 400    -- ms floor between presses
local last   = 0

function tick()
  if POEMEMORY.Area.InTown then return end
  if POEMEMORY.Player.Life.Pct > THRESH then return end
  if now() - last < GAP then return end

  local s = POEMEMORY.Player:SkillByKey(KEY)
  if not (s and s.Ready) then return end   -- nil on the first ticks, or cooling

  last = now()
  Input.Press(KEY)
end

The order of the checks matters. The cheap checks (town, life, timer) come first. The skill bar is only read when the rest already says "yes".

2 · Intermediate

several skills, one priority list

intermediateCooldown rotation by priorityneeds input

A list of cooldown skills, most important first. Each time it may press, it casts the first ready skill in the list. Your big skill always goes out the moment it is back; the smaller ones fill the gaps.

Tune: ROTATION (keys, best first), RANGE, MANA (minimum mana percent), GAP.

local ROTATION = { "R", "T", "Q" }   -- highest priority first
local RANGE    = 45                  -- only fight when monsters are this close
local MANA     = 15                  -- don't cast below this mana percent
local GAP      = 350                 -- ms floor between presses
local last = 0

function tick()
  if POEMEMORY.Area.InTown then return end
  if now() - last < GAP then return end
  if POEMEMORY.Player.Mana.Pct < MANA then return end
  if POEMEMORY.World.Monsters:CountWithin(RANGE) == 0 then return end

  for _, key in ipairs(ROTATION) do
    local s = POEMEMORY.Player:SkillByKey(key)
    if s and s.HasCooldown and s.Ready then
      last = now()
      Input.Press(key)
      return                         -- one skill per press
    end
  end
end

Why s.HasCooldown: a skill with no cooldown is always ready. Put one in the list and it would win every time and block the skills below it. This rotation is for cooldown skills only.

Skills with more than one use (a support gem that adds uses) just work: .Ready stays true while any use is left.

3 · Advanced

rules per skill, and a check that the cast really happened

advancedSituational skills with cast checkneeds input

Each skill gets its own rule: save the big one for rares and uniques, use the area skill on packs, and the small one on anything. After each press the script watches .CastCount. If the count does not go up, the cast failed (no mana, stunned, wrong key), and that skill gets a short pause instead of being pressed again and again.

Tune: the RULES list (key + condition), CONFIRM, BACKOFF, GAP.

-- first matching rule wins; M is POEMEMORY.World.Monsters
local RULES = {
  { key = "T", when = function(M)            -- big cooldown: bosses only
      return M:UniqueCountWithin(60) > 0 or M:RareCountWithin(50) > 0 end },
  { key = "R", when = function(M)            -- area skill: real packs only
      return M:CountWithin(35) >= 8 end },
  { key = "Q", when = function(M)            -- filler: anything close
      return M:CountWithin(30) >= 1 end },
}
local GAP     = 300    -- ms floor between presses
local CONFIRM = 800    -- ms to wait for the cast to show up
local BACKOFF = 3000   -- ms to skip a key whose press did not cast

local last      = 0
local pending   = nil  -- the last press: { key, count, at }
local skipUntil = {}   -- key -> time it may be used again

function tick()
  if POEMEMORY.Area.InTown then return end
  local t = now()

  -- 1. did the last press really cast?
  if pending then
    local s = POEMEMORY.Player:SkillByKey(pending.key)
    if s and s.CastCount > pending.count then
      pending = nil                              -- yes: carry on
    elseif t - pending.at > CONFIRM then
      log(pending.key .. " did not cast - pausing it")
      skipUntil[pending.key] = t + BACKOFF       -- no: give it a rest
      pending = nil
    else
      return                                     -- still waiting to see
    end
  end

  -- 2. pick the first rule that is ready and wants to fire
  if t - last < GAP then return end
  local M = POEMEMORY.World.Monsters

  for _, r in ipairs(RULES) do
    if t >= (skipUntil[r.key] or 0) then
      local s = POEMEMORY.Player:SkillByKey(r.key)
      if s and s.Ready and r.when(M) then
        last = t
        pending = { key = r.key, count = s.CastCount, at = t }
        Input.Press(r.key)
        return
      end
    end
  end
end

Why check .CastCount: a key press that does nothing looks exactly like one that works. .Ready does not know about mana, so without this check the script would hammer a skill you cannot afford. The count goes up by 1 on every real cast, so it is the honest answer.

Add your own rules — any test works inside when, for example POEMEMORY.Player.Life.Pct < 40, or M:CountMatching("Volatile", 30) > 0.

4 · Targeting

aim the skill at the nearest enemy — but prefer rares and uniques

expertAim at the best target, rarity firstneeds input

Scores every monster on screen in range. Close is good; higher rarity is better. The best one gets a colored box. When the skill is ready, the cursor moves onto that target and the skill is cast there. The script also sticks to its target a little, so the aim does not flicker between two monsters at the same distance.

Tune: KEY, RANGE, PULL (how much rarity counts, see below), STICK, GAP, MARK.

local KEY   = "Q"     -- the skill to aim and cast
local RANGE = 60      -- only targets this close (grid units)
local PULL  = 15      -- grid units each rarity step is worth
local STICK = 5       -- bonus for the target we already have
local GAP   = 400     -- ms floor between casts
local MARK  = true    -- draw a box on the chosen target

local RANK  = { Normal = 0, Magic = 1, Rare = 2, Unique = 3 }
local COLOR = { Normal = "cccccc", Magic = "6b8cff", Rare = "ffd000", Unique = "ff8000" }

local last     = 0
local targetId = nil  -- the Id we picked last tick (an Id, never the handle)

-- lower score wins: distance, minus a bonus for rarity and for sticking
local function score(m)
  local sc = m.Distance - (RANK[m.Rarity] or 0) * PULL
  if m.Id == targetId then sc = sc - STICK end
  return sc
end

local function pickTarget()
  local best, bestScore = nil, math.huge
  for _, m in ipairs(POEMEMORY.World.Monsters:Within(RANGE)) do
    if m.OnScreen and m.IsAlive then
      local sc = score(m)
      if sc < bestScore then best, bestScore = m, sc end
    end
  end
  return best
end

function tick()
  if POEMEMORY.Area.InTown then targetId = nil return end

  local m = pickTarget()
  if not m then targetId = nil return end
  targetId = m.Id
  if MARK then m:Mark(COLOR[m.Rarity] or "ffffff") end

  if now() - last < GAP then return end
  local s = POEMEMORY.Player:SkillByKey(KEY)
  if not (s and s.Ready) then return end

  last = now()
  Mouse.Move(m.ScreenX, m.ScreenY)   -- aim
  Input.Press(KEY)                   -- cast at the cursor
end

How PULL works: each rarity step takes PULL grid units off the distance. With PULL = 15, a rare 35 units away (35 − 30 = 5) beats a normal monster 10 units away. A rare 60 units away (60 − 30 = 30) does not.

Two extremes: PULL = 0 is plain "nearest monster". PULL = 1000 is strict "highest rarity first, nearest only breaks ties".

Skill on a mouse button? Use POEMEMORY.Player:Skill(3) to read it, and replace the last two lines with Mouse.ClickAt(m.ScreenX, m.ScreenY, "right").

Why remember an Id: monster handles must not be kept between ticks. The .Id number is stable, so the script keeps that and finds the monster again in the next tick's list.
